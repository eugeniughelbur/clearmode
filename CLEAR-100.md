# CLEAR-100

**Clear Language for Every Actual Reader.** 43 rules on 4 axes for text produced with AI, aimed at the person who has to read it.

## Why it exists

In the 1980s the European aerospace industry wrote [ASD-STE100 Simplified Technical English](https://www.asd-ste100.org/) because an ambiguous line in a maintenance manual is a safety problem. A mechanic under a wing cannot ask the author a follow-up question. STE fixed that with 53 rules and about 900 approved words: one meaning per word, active voice, short sentences, one instruction at a time.

STE works. It also reads like a machine, on purpose. It bans contractions, bans the semicolon, and cares nothing about whether a human enjoys the page, because a human enjoying the page was never the goal.

Two things changed. Most text is now drafted by a model, which means the failure mode is no longer ambiguity. It is filler that scans as competent. And most of that text is read by people outside the field it came from, on a phone, deciding in one screen whether to keep going.

So CLEAR-100 keeps the STE discipline and adds what STE never needed:

- A **human** axis, because text that reads synthetic gets discounted before it gets read.
- A **structured** axis, because the shape of a page decides whether it gets read at all.
- A **dense** axis, because the real complaint about AI writing is not vocabulary. It is that nothing is being said.

## What it is not

- Not a detector. It does not guess whether a model wrote something. It measures whether a person can read it.
- Not a compliance claim against ASD-STE100. That standard's approved-word dictionary is ASD's copyright and is not reproduced here.
- Not a style opinion. Every rule states its failure mode and its fix. Disagree with a rule by changing the rule pack, not by ignoring the output.

## How to use it

The standard is data, not prose. `rules/clear-100.json` is the single source of truth. The checker reads it, and every agent target is compiled from it, so a rule change propagates everywhere in one command.

```bash
python3 scripts/clearcheck.py FILE --profile general
python3 scripts/compile_targets.py
```

Four axes, weighted into one score out of 100. Default gate is 80.

## Axis P: Plain (30%)

A reader outside your field understands it on the first pass, with no dictionary and no follow-up question.

| Rule | Severity | Do this |
|---|---|---|
| **P1** One sentence, one length limit | warn | Split at the conjunction. Two short sentences always beat one long one. |
| **P2** One instruction per sentence | warn | Make it a numbered list. One step per line. |
| **P3** No semicolons in reader-facing prose | review | Use a period. Start a new sentence. |
| **P4** Active voice for anything a person does | warn | Put the actor first. Subject, verb, object. |
| **P5** Use the short word | warn | Swap in the plain alternative from the substitution table. |
| **P6** Gloss jargon on first use | warn | On first use, add a short plain gloss in parentheses or in the next clause. Never gloss twice. |
| **P7** Expand an acronym on first use | warn | Write it out once, then use the short form. Skip this only for acronyms your whole audience already owns. |
| **P8** Hold the reading grade | warn | Shorten sentences first, then swap long words. Those two moves carry almost all of the score. |
| **P9** Cap noun stacks | review | Break the stack with a preposition. |
| **P10** Unbury the verb | warn | Use the verb itself. |
| **P11** Keep contractions | review | Use don't, can't, it's, you're where a person would say them out loud. |
| **P12** Numerals and units, not adjectives | review | Replace with the count, the percent, or the duration. |

## Axis H: Human (30%)

It reads like a person who did the work, not like a model that read about the work.

| Rule | Severity | Do this |
|---|---|---|
| **H1** No slop vocabulary | error | Say the specific thing the word was standing in for. If nothing specific is behind it, delete the sentence. |
| **H2** No slop phrases | error | Delete. If the sentence dies without the phrase, the sentence was the phrase. |
| **H3** No canned sentence openers | warn | Start with the subject of the new fact. Or cut the sentence. |
| **H4** No em-dash, no en-dash used as one | error | Use a period and a new sentence, a comma, a spaced hyphen, or parentheses. |
| **H5** Straight quotes and apostrophes | warn | Use straight quotes. |
| **H6** No negative parallelism | error | State the claim once, directly. |
| **H7** Break the rule of three | warn | Use two items, or four, or make it a real list with real content per item. |
| **H8** Say is, not serves as | warn | Use is, are, or has. |
| **H9** No promotional adjectives | warn | Replace with the measurement or the mechanism. |
| **H10** No trailing -ing analysis | warn | Cut the clause. If the point matters, make it its own sentence with a fact in it. |
| **H11** Name the source or drop the claim | warn | Name the study, the person, and the year, with a link. Or write it as your own claim. |
| **H12** No assistant voice | error | Delete. Published text has no counterparty to be polite to. |
| **H13** Vary sentence length | warn | Put a four-word sentence next to a 28-word one. Read it out loud. |
| **H14** No model self-reference | error | Delete the sentence and answer the question, or say the fact is unverified and why. |
| **H15** Do not announce that you are stopping | warn | Stop. Or end on the strongest concrete fact. |
| **H16** No hedge stacking | review | Say the thing, or say the exact limit of what you know. |

## Axis S: Structured (25%)

The shape of the page matches the shape of the information. Lists look like lists, steps look like steps.

| Rule | Severity | Do this |
|---|---|---|
| **S1** Three parallel items become a list | warn | Break the sentence into a bulleted list, one item per line. |
| **S2** Sequences become numbered steps | warn | Numbered list. One action per number. |
| **S3** Comparisons become a table | review | Write the table. |
| **S4** Cap paragraph length | warn | Break at the topic shift. Blank line between paragraphs. |
| **S5** One topic per paragraph | review | Split. Give each its own paragraph, and a heading if it earns one. |
| **S6** Heading levels do not skip | warn | Go h2 then h3. Never h2 then h4. |
| **S7** Sentence-case headings | warn | Capitalize the first word and proper nouns only. |
| **S8** Bold is for one thing per screen | warn | Keep bold under five percent of words. One idea per section. |
| **S9** No emoji as structure | warn | Use real bullets and real headings. |
| **S10** Long pieces lead with the answer | warn | Open with the conclusion in one to three lines, then the detail. |

## Axis D: Dense (15%)

Every sentence carries information a reader could not have guessed. Delete it and the piece loses something.

| Rule | Severity | Do this |
|---|---|---|
| **D1** The delete test | warn | Delete it, or replace it with the fact it was gesturing at. |
| **D2** No restatement | warn | Keep the sharper one. Delete the other. |
| **D3** No throat-clearing opener | error | Lead with the number, the name, or the claim. |
| **D4** The horoscope test | review | Anchor it to your specific case: a name, a date, a number, a file, a failure. |
| **D5** No filler intensifiers | warn | Delete the intensifier. If the claim now looks weak, the claim was weak. |

## Scoring

Every finding costs its rule weight, multiplied by severity (error 2.0x, warn 1.0x, review 0.4x), normalized per 250 words. Each axis starts at 100. The document score is the weighted mean of the four axes. Default gate is 80.

| Score | Band | Verdict |
|---|---|---|
| 90+ | A | ship it |
| 80+ | B | ship after the errors |
| 65+ | C | one rewrite pass needed |
| 45+ | D | rewrite, do not patch |
| 0+ | F | this reads like a model wrote it |
